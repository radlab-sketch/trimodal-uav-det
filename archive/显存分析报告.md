# 显存分析报告

## 数据加载方式分析

**结论：不存在预先存入显存的训练数据。**

从 `trimodaldet/data/dataset.py` 代码分析（已备份到 `archive/dataset.py.original`）：

```python
def __getitem__(self, idx):
    # 每次调用时从磁盘加载单个 .npy 文件
    img_path = os.path.join(self.image_dir, self.image_files[idx])
    image = np.load(img_path)  # 从磁盘读取
    image_tensor = torch.from_numpy(image).float()  # CPU 张量
    ...
```

训练循环中：
```python
images = list(image.to(self.config.device) for image in images)  # 每 batch 移到 GPU
```

数据加载流程：**磁盘 → 内存 → GPU（每 batch 按需）**，没有预加载到显存。

## 显存占用分析

| 配置 | 显存占用 | 结果 |
|------|---------|------|
| batch_size=1, mit_b1 | 7201 MB (44.2%) | ✅ 成功 |
| batch_size=2, mit_b1 | 9283 MB (57.0%) | ✅ 成功 |
| batch_size=4, mit_b1 | ~19000 MB (116%) | ❌ OOM |
| batch_size=4, mit_b0 | 未测试 | 待验证 |

**模型参数显存**：
- Backbone (mit_b1): 174 MB
- 完整模型 (Faster R-CNN): 229 MB

**中间激活值**：
- batch_size=1 时 forward 增量约 4500 MB
- batch_size=4 时 forward 增量约 18778 MB

显存占用高的主要原因是 **Faster R-CNN 检测头的中间激活值**（RPN proposal + RoI 池化），而非数据加载。

## 优化建议

1. **batch_size 调整**：
   - RTX 5080 16GB 显存，mit_b1 建议 batch_size=1 或 2
   - 使用梯度累积（accumulation steps）保持等效 batch_size

2. **Backbone 调整**：
   - mit_b0 参数更少（~3.7M vs ~13.5M），可尝试 batch_size=4

3. **混合精度训练**：
   - 使用 `torch.cuda.amp.autocast()` 可节省约 40-50% 显存

4. **定期清理**：
   - 已在 trainer.py 中每 100 batch 调用 `torch.cuda.empty_cache()`
